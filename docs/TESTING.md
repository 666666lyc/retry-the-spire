# 回归检查

## 可重复的离线检查

回归程序不依赖 NuGet 测试框架，运行时只从指定安装目录加载游戏程序集。
它不启动游戏、不连接 Steam、不读写真实存档；文件恢复测试使用内存中的 `ISaveStore` 替身。
需先构建 Mod，再在仓库根目录运行：

```powershell
.\build.ps1 -GameDir 'C:\path\to\Slay the Spire 2'
dotnet run --project tests/Regression -- check `
  out/RetryTheSpire/RetryTheSpire.dll `
  'C:\path\to\Slay the Spire 2\data_sts2_windows_x86_64' `
  tests/Regression/Fixtures
```

macOS / Linux 也使用相同参数；将第二个路径替换为游戏实际的程序集目录。
任何检查失败时返回非零退出码。该项目使用自己的 `bin/` 和 `obj/`，不进入 Mod 编译和发布包。

27 项检查覆盖：

- 原有公开 API、Harmony 补丁目标及补丁注册顺序。
- 快照 v5 原始载荷、压缩封装往返、异常载荷拒绝、v4 合成数据迁移、去重与 blob 整理。
- 裁剪保护当前对局、优先删除不在历史中的记录，以及配置档切换时的缓存状态。
- 主文件损坏后的备份恢复、主文件优先、无文件、正常轮换、保留恢复备份、重命名失败回滚及临时文件校验。
- 控制包与直载包封装字节、消息枚举、协议与超时常量；截断、超长、版本、类型、保留位、长度、通道和传输模式校验。
- 历史切片的章节/目标边界、条目身份及原始列表不被修改；药水槽缩减时的迁移和丢弃顺序。
- 重试尝试重置与连接能力隔离，过期 host/generation/nonce 会话拒绝，浏览器会话独立持有预览状态。

## 基线样例

`tests/Regression/Fixtures/` 来自重构前 v0.7.0 程序集：公开 API 与补丁描述、原注册顺序、
协议参数、合成地图/玩家 blob 的 v5 二进制载荷、v4 迁移结果和原始网络封装。
样例不包含实际存档、游戏 DLL 或游戏资源。二进制样例中的地图和玩家 blob 是不透明的合成字节，
不代表可直接载入游戏的完整对象；原生对象序列化和游戏加载仍需下方的游戏回归。

`capture` 模式只用于从可信的原始程序集生成基线；不要用重构后的程序集覆盖样例来消除失败。
