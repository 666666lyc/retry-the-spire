# 保留问题

本次只整理结构与职责，未改变以下原有行为。

- 六处空引用编译警告仍保留：浏览器会话、浏览器诊断、库存注入各一处，以及放弃对局处理三处。
  修正需要单独验证游戏对象生命周期，未用抑制标记或强制非空断言隐藏警告。
- `RetryRunner.Begin` 的 `targetCoord` 参数仍保留；原有 `BeginInternal` 没有将此参数传入恢复目标，
  实际落点沿用现有的历史路径和快照坐标逻辑。本次不调整该行为。
- 配置档加载切换时，原实现不主动清空 `_lastGoodPayload`；本次维持原有回滚语义，
  后续需单独验证“切换配置档后首次写入超限”的回滚边界。

真实游戏的 UI、进度解锁、Steam Cloud 与双端联机回归尚未执行。自动化检查的范围和待验证场景见 [TESTING.md](TESTING.md)。


## v0.8.0 兼容边界

- 同一个 DLL 支持正式版 v0.111.1 与测试版 v0.113.1，但完整原生房间快照按游戏构建隔离；构建不符时保留数据并拒绝恢复。

- 实际双端联机、可见 UI 和新模式无完整快照重建的覆盖边界见 TESTING.md 的 2026-11-17 记录。
